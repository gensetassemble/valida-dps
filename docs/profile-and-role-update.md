# Pembaruan profil dan akses akun — 29 Oktober 2026

Form profil pengguna memakai Nama, Email, NPP, WhatsApp, dan Password, dengan status Aktif terpisah. UUID dan pilihan identitas terverifikasi tidak diminta dari operator. Server mengaitkan email ke Auth dan mencocokkan NPP dengan direktori cabang. NPP boleh kosong untuk Non-NPP; tautan pegawai Non-NPP yang sudah sah dipertahankan saat diedit. Aktivasi tetap mengikuti status pegawai pada direktori.

Password hanya tampil dan dapat diproses untuk peran eksplisit Super Admin di cabang terkait. Password kosong mempertahankan kredensial lama atau menautkan akun Auth yang sudah ada. Password terisi pada profil baru membuat akun Auth tanpa mengirim email; peran harus ditugaskan terpisah. Pada profil lama, identitas dan otorisasi diperiksa dahulu sebelum password Auth diganti. Password tidak menjadi kolom profil, tabel, detail, atau audit. Jika penyimpanan profil baru gagal, akun Auth yang baru dibuat dibersihkan. Jika reset gagal setelah identitas disimpan, pesan menyebutkan hasil parsial tersebut.

Konfigurasi server `SUPABASE_SECRET_KEY` (atau legacy `SUPABASE_SERVICE_ROLE_KEY`) dari proyek yang sama wajib tersedia secara lokal dan di environment Vercel yang digunakan. Kunci ini tidak boleh memakai prefiks `NEXT_PUBLIC_`. Tanpa kunci server, pengelolaan password menampilkan pesan konfigurasi sebelum melakukan perubahan. Alur tanpa password tetap dapat menautkan akun yang sudah ada.

Kegagalan halaman Kalibrasi Alat pada PTK direproduksi sebagai PostgreSQL `57014` (statement timeout). View monitoring membaca kalibrasi melalui lateral join; pemeriksaan role/portofolio yang bertingkat diulang pada banyak kandidat baris. Kebijakan SELECT kini memakai himpunan scope yang dihitung sekali per statement. Kebijakan tulis tetap memakai pemeriksaan yang sama. SELECT alat memakai portofolio baris agar INSERT RETURNING dan transaksi tambah alat + kalibrasi awal tetap berhasil.

Dashboard PTK berfokus pada kalibrasi, AM pada sertifikat klien, dan HRGA pada kompetensi. Koordinator memiliki kompetensi dan kalibrasi; QSHE, Tester, pimpinan, dan Super Admin tetap membaca modul sesuai kewenangan cabang. Parameter kategori tidak dapat memunculkan modul yang tidak diizinkan. Form satu alat menggunakan tabel Parameter | Isian pada desktop dan label/isian bertumpuk pada ponsel.

Browser PTK berhasil membuka daftar 173 alat. Pembacaan penuh view ketiga modul diperiksa pada sepuluh akun workflow dan sesuai cakupan. Regresi SQL fase 02, fase 03–04, workflow role, profil, dan jendela perpanjangan lulus. Tes workflow menambah alat/kalibrasi sebagai PTK lalu membaca hasilnya, seluruhnya dalam transaksi rollback. Unit test mencakup otorisasi password, kompensasi pembuatan akun, kegagalan reset, profil tanpa UUID, dan pembatasan dashboard. Pengujian Auth admin langsung tetap membutuhkan kunci server tersebut.
